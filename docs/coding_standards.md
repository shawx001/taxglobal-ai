# TaxGlobal AI 代码编写规范（Coding Standards）

日期：2026-06-02
状态：生效（v1.0）
适用：Codex 写码 + Claude review 共同遵循。
与现有文档关系：细化 `engineering_process.md`（Develop 阶段）与开发计划"工程质量底线/大厂工程规范"到**写码层面**，不重复其内容。

> 原则：规则全部作为长期标准保留；但按当前 MVP（单人 + Python stdlib 引擎 + 暂无 DB/并发/外部调用）标注**何时生效**。在没有对应场景时强行套用（如给纯函数加分布式锁、给无外部调用加指数退避）本身就是过度设计。

---

## 一、接口先行与防御性设计

| 规则 | 在本项目怎么落地 | 何时生效 |
|---|---|---|
| 输入必校验（不信任何外部输入） | engine 已校验 `filing_status`、clamp 负收入；API 入口用 **Pydantic** 强校验类型/边界/长度；规则 JSON、KB 条目入库前校验 schema | engine 现在；API → Step 4；KB → Step 6 |
| 类型安全，禁止 `any` 掩盖 | Python 全量 type hints + 引入 **mypy/pyright**；禁用 `Any` 兜底；前端 TS `strict` 仅在迁 Next.js 后适用（当前 plain JS） | 类型检查建议随 CI 接（M3/Step 4）；TS 暂不适用 |
| 默认不可变 | engine 已是纯函数 + loader 返回 `deepcopy`；规则 dict 视为只读；新代码默认只读、不就地改参 | 现在生效 |

## 二、异常处理三板斧

| 规则 | 在本项目怎么落地 | 何时生效 |
|---|---|---|
| 不吞异常 | 禁止空 `except` / `except: pass`；至少记录 + 重抛或转友好错误 | 现在生效 |
| 显式分类 | **业务异常**（不可算/输入非法）→ 用 `not_covered` 等结构化友好返回，不抛栈；**系统异常**（IO/DB/网络）→ 详细日志 + 告警。engine 现以 `not_covered` 表达"业务上不可算"，不是抛错 | 现在生效（分类思路）；告警 → Step 5 |
| 兜底 + 重试（Timeout / 指数退避 / 降级） | 仅对**不稳定外部调用**适用：KB 官方来源抓取、未来连接器。当前 engine 无外部调用，**不适用**（加了就是过度设计） | Step 10（KB 抓取）/ 连接器阶段 |

## 三、可观测性

| 规则 | 在本项目怎么落地 | 何时生效 |
|---|---|---|
| 日志规范（核心逻辑必打，含 谁/操作/结果/耗时） | 计算、状态流转、KB 命中/未命中打结构化日志。纯函数 engine 现可不打（无副作用）；API 层强制 | Step 4 起 |
| TraceID 链路标识 | 每请求注入 `request_id`，串联整条链路日志（开发计划已要求日志保留 request id / rule_version / knowledge_id） | Step 4 起 |
| 杜绝硬编码 | 密钥/端口/URL → `.env`；**税率/阈值 → 已在 `data/`（项目核心原则）**；产品阈值（如 `NEXUS_APPROACHING_RATIO=0.80`）放命名常量/配置，不散落 | 数据/阈值现在生效；.env → Step 4 |

## 四、数据库与并发安全（当前无 DB，**Step 9 起生效**）

| 规则 | 在本项目怎么落地 |
|---|---|
| 事务原子性（ACID） | 多表更新（计算记录 + 审计日志）放单事务，事务尽量短、避免长事务锁表 |
| 防并发冲突 | 共享资源用乐观锁（version 字段）或分布式锁；**当前单机无并发，暂不适用** |
| SQL 红线 | 禁止 `SELECT *`（按需取列）；查询必须命中索引；严禁全表扫描；审计/历史表设计时落实 |

## 五、TDD 与原子化重构（**现在生效**）

| 规则 | 在本项目怎么落地 |
|---|---|
| 单测与代码同行 | Codex 交函数必交单测，覆盖**正常流 / 边界值(0/空/极大) / 异常流**三类。M3 黄金测试即此原则的集中体现；SE/nexus 必须随实现交测试 |
| 单一职责（SRP） | 一函数只做一件事，尽量 < 50 行、优先纯函数。决策 **SE-4**（SE 函数不掺所得税）就是这条 |
| 持续微重构 | 发现为堆功能复制粘贴 → 立即提取公共模块（如已抽出的 `_response` / `_not_covered` / `_money`）。Claude review 会盯重复代码 |
| 引擎模块边界 | engine 采用门面 + 小模块结构：`engine/__init__.py` 暴露公共 API，`engine/tax_engine.py` 仅作兼容 shim；新增能力优先落在 `federal/payroll/qbi/feie/state/crypto/rsu/nexus/summary` 等领域模块，不把新逻辑继续堆回上帝文件 |

## 六、上线工程标准（企业级；设计阶段即考虑，实现按场景生效）

> 本服务面向**真实上线**（高并发、多用户）。前几节已覆盖 DRY / 异常 / DB / SQL；本节补上线必须的额外要求。核心一句：**“功能跑通”不是终点，要按资深工程师标准设计——可复用、抗并发、幂等、为后续 DB/知识库打企业级地基。** 仍守“无场景不硬套”（纯函数不加分布式锁），但**设计时就要为这些场景留好结构**。

| 规则 | 在本项目怎么落地 | 何时生效 |
|---|---|---|
| 抗高并发（横向可扩） | 请求 handler 无状态、引擎纯函数（无共享可变态）；热只读数据缓存（规则 JSON 已 `@lru_cache`）；热路径不做每请求磁盘/网络 I/O；无 N+1；注意前端扇出（必要时做 batch 端点） | 设计现在；DB/连接器实现时强化 |
| **幂等（适当处）** | 重试/重复提交必须安全。**计算引擎已幂等**（纯函数、无副作用）。真正吃劲在**写**：计算记录/审计持久化、KB 入库、定期规则更新、外部/支付调用 → 用**幂等键 / upsert / 去重**，保证重试或双提交不脏数据、不重复计 | DB → Step 9；KB 入库 → Step 6/10；连接器阶段 |
| 企业级 DB + 知识库 | Step 6–10 按资深工程标准：schema 设计 + 迁移、连接池、命中索引（无 N+1）、事务、**幂等入库**、缓存与失效、可观测（已有 request_id/审计），且贯穿“每个数字/结论可溯源到归档官方源”。**不是原型水平** | Step 6–10 |
| 可复用 | 复用现有引擎原语与 `_response`/`_not_covered`/`_money`/`_state_taxable_base` 等；新代码与既有模式一致；不复制粘贴 | 现在生效 |

**写 Codex prompt 时**：凡涉及上述场景，把“可复用 / 抗高并发 / 幂等（写操作）/ 企业级 DB-KB”**显式写进 prompt 的约束区**，不默认 Codex 会想到；review 时按本节逐条核。

## Claude Review 检查清单（每次 review 按此逐项对照）

- [ ] 输入是否校验：类型 / 边界 / 未知值是否显式处理（不是默默放过）
- [ ] 异常：无空 `except`、是否分类（业务 vs 系统）、是否吞错
- [ ] 硬编码：无裸写税率 / 密钥 / URL / 业务阈值
- [ ] 不可变：纯函数 / 只读，无意外就地修改共享数据
- [ ] 测试：单测随代码交付，覆盖 正常 / 边界 / 异常 三类
- [ ] 结构：单一职责、函数 < 50 行、无复制粘贴
- [ ] 类型：有 type hints，无 `Any` 掩盖
- [ ] （Step 4+）TraceID / 结构化错误 / 外部调用超时重试
- [ ] （Step 9+）事务原子性 / 并发锁 / SQL 红线（无 `SELECT *`、命中索引）
- [ ] 可复用：复用现有引擎原语/公共件，不复制粘贴；与既有模式一致（见 §六）
- [ ] 上线/抗并发：无状态、纯函数、热数据缓存、热路径无每请求 I/O、无 N+1（设计期考虑，按场景实现）
- [ ] 幂等（写操作）：DB 写 / KB 入库 / 外部调用，重试或重复提交是否安全（幂等键 / upsert / 去重）

## 七、防屎山 / 模块化纪律（vibe-coding 调研 + Step A.5 经验）

> 根目录 **`AGENTS.md`** 是"Always 铁律"入口（Codex/Claude 每次开工先读）；本节是其展开。核心：**planning-driven + 固定上下文 + 模块化 + 硬门禁 + 不自我认证**。

- **禁巨石文件（no monolith）**：单文件不堆成上帝文件（曾有 1820 行 `tax_engine.py`，已按领域拆成 `engine/` 包 + 门面）。模块/文件一旦"什么都管"就拆；每模块单一职责。
- **接口先行（接口先行，实现后补）**：先有设计文档/函数契约（`docs/*_design_*.md`），再写实现；每步设计文档列输入/输出/边界。
- **数据驱动，不特判**：规则=声明式数据 + 通用解释器；**不写按州名/个案的 if/elif 分支**（新州/年=只改数据）。
- **行为不变重构有安全窗**：golden 覆盖最全时做纯重构最安全（全绿即证零行为变化）；别等堆大了再拆。
- **最小改动**：只动相关文件，不顺手重构无关代码；diff 小、可审。
- **固定上下文/可续接**：`feature_status.md`（进度）+ `ARCHITECTURE.md`（架构/抗压边界）+ 设计文档 + 记忆，构成 "memory-bank"；换对话先读这些再续。
- **不自我认证 → 硬门禁**：AI"应该没问题"不算数；可测的都变成 ruff/unittest/数据校验/CI/golden 门禁（见 AGENTS.md §D）。Claude 额外做独立逐分重算，不只信引擎自身输出。
- **一步一 PR**：小而可验证；语义化 commit；PR step-0 提交未跟踪的设计/标准文档。
