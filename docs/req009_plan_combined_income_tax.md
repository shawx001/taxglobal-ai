# REQ-009 方案 — 全收入合并计税(总税)拆块计划

日期：2026-06-03
阶段：PLM 阶段 2（Design，总体方案;每块再出独立设计 + Codex prompt）
依据：现有引擎(`income_tax_summary`/`self_employment_tax`/`fica_tax`/`qbi_deduction`/`bracket_tax`/`state_income_tax`/`crypto_gain_estimate`/`feie_estimate`)、REQ-009、REQ-002
角色：Claude 出方案 + 每块设计 + Codex prompt;Codex 实现;Shaw 拍板。

> 目标:把一个人的**全部收入桶**(W-2 / 自雇 / RSU / 加密利得 / 海外赚取收入)按 IRS **正确叠加顺序**算成**唯一正确的总税**。复用已有引擎,**不重写税法**——难点是"**不能各算各的再相加,要喂同一上下文、按顺序算**"。

---

## 1. 架构(已定)
- **扩 `income_tax_summary`(不新建函数)**:它已是合并器(自雇+联邦+州+QBI,且留了 `other_ordinary_income` 口子)。新增**可选入参,全部默认 0/None → 向后兼容**(自雇前端 `/calc/income-summary` 不受影响)。
- **复用现有引擎件**,只新增"按正确顺序编排 + 几个组合量"的逻辑。纯函数、Decimal、规则只来自 `data/`。

## 2. 为什么不是"各算各的一加"——7 个交叉点(每个都是错数来源)
1. **累进叠加**:W-2 + 自雇 + RSU 普通收入要**叠在一起**定边际档(各自从 0 起算 → 低估)。
2. **社保工资基数共享**:SS 基数 \$176,100 在 W-2 与自雇**之间共享**——W-2 先占,自雇 SS 只对剩余基数征。各自算 = 各用满 176,100 → **高估**自雇 SS。
3. **附加医保单一阈值**:0.9% 看 **(W-2 + 自雇净earnings) 合计**过没过单一阈值(单身 200k)。各自算各减一次阈值 → 既可能漏(合计才过)也可能重(各减一次)。
4. **QBI 基数只含经营收入**:20% QBI **不含 W-2/RSU**,只对自雇/经营。合并时 `qbi_amount` 必须排除 W-2。
5. **长期利得叠加(LTCG)**:0/15/20% 看**含全部普通收入后的总应税收入**(孤立算常落 0% → 漏税,前面 \$40k 例子差 \$6,000)。
6. **NIIT 按总 MAGI**:3.8% 投资净收益,阈值看**总 MAGI**(工资+自雇+利得)过没过 200k。
7. **FEIE 税率叠加(Form 2555)**:海外收入豁免后,**剩余收入按"含被豁免额"的税率档**计——孤立算 FEIE 会把剩余部分税率算低。

(扣除项也只减一次:标准扣除、½SE 抵扣。)

## 3. 主算法(正确顺序)
```
普通收入 = W-2 + 自雇净利 + RSU/其它普通 + 短期利得 + (海外赚取 − FEIE 豁免)
above_line = ½SE(合并 SE) + SE健保 + 退休
AGI = 普通收入 − above_line
qbi_amount = 自雇经营部分(排除 W-2/RSU)
taxable = max(0, AGI − 标准/指定扣除 − QBI)
联邦普通税 = bracket_tax(taxable)              # FEIE 时用"含豁免额"的税率(§7)
长期利得税 = LTCG 断点叠在 taxable 之上(§5)
合并工资税 = 共享 SS 基数的 W-2 FICA + 自雇 SE 税(§2) + 单一阈值附加医保(§3)
NIIT = 3.8% × min(投资净收益, 总MAGI − 阈值)     # §6
州税 = 各州税基(普通收入 + 利得按各州规则)
总税 = 联邦普通 + 长期利得 + 合并工资税 + NIIT + 州税
+ 有效税率、季度预缴
```

## 4. 拆块(一块一块,每块都算准 + 黄金值 + 我逐分验)
- **Block 1 — 赚取收入总税(W-2 + 自雇)**:普通收入累进叠加(§1)+ **合并工资税**(§2 共享 SS 基数 + §3 单一附加医保阈值)+ QBI 基数排除 W-2(§4)+ 州税。**这是地基,也含两个最棘手的工资税交叉点。** RSU 归属值并入 W-2/普通收入(其 FICA 通常已在 W-2 上)。
- **Block 2 — 加上资本利得**:长期利得叠加(§5)+ NIIT 按总 MAGI(§6)。复用 `crypto_gain_estimate` 的 LTCG/NIIT 逻辑,但喂"合并后的普通收入"做 stacking 基数。
- **Block 3 — 加上海外(FEIE)**:`feie_estimate` 豁免 + **Form 2555 税率叠加**(§7)——剩余收入按含豁免额的税率档计。

> 顺序理由:Block 1 是其它块的 stacking 基数(必须先有"普通收入总额");Block 2 叠在其上;Block 3 改变税率档。每块向后兼容(新参数默认 0)。

## 5. 诚实边界(贯穿各块)
- 各块对未建模项(州残余调整、AMT、ISO/ESPP、被动海外/FTC、洗售、$3000 净亏抵扣/结转、受养人等)继续 `assumptions` 标注、不伪造。
- `other_ordinary_income` 口径(普通应税收入近似)沿用现有 MVP 假设并标注。
- 每块都跑黄金值 + 我独立逐分核(尤其 §2/§3 工资税交叉、§5 LTCG 叠加、§7 FEIE 税率叠加)。
